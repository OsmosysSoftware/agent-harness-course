Skills: procedures the agent runs by name

A prompt you paste is a copy, and copies drift. A skill is the procedure kept as one file in the repo, which the agent loads by name and follows step by step, the same way in every session.

12 min read 45 min exercise Plaque: Skill Smith
In 30 seconds
  • A skill is a folder with a SKILL.md: a name, a description, and steps. You run it with /name, or the agent picks it from the description.
  • It lives in git, so a fix is one reviewed commit and every later session gets it.
  • You add two: commit, a checkpoint line every commit passes through, and quality-gate, which runs a script. Then you watch both refuse.

A plan that arrives in the same commit as the code, every box ticked, proves nothing about order. Committed alone and first, it shows the change was decided before it was built.

What a skill is

A skill is a folder holding a SKILL.md file: a short YAML header (the block between --- lines), then instructions in Markdown. Claude Code loads every skill's description at the start of a session, and the full body "only loads when invoked" (Skills). So ten skills cost you ten descriptions, not ten procedures.

PartWhat it does
nameThe command you type, /commit. Defaults to the folder name.
descriptionWhat it does and when to use it. The agent reads this to decide on its own when the skill applies, so the key use case goes first.
BodyThe steps, in order. It enters the conversation when the skill runs.
Other filesAnything else in the folder: reference notes the body links to, or a script the steps run. They load only when needed (the docs call this progressive disclosure).

Two ways a skill starts. You type /name, or the agent picks it because your request matches its description. Two header lines change that: disable-model-invocation: true means only you can start it (the docs suggest it for side effects such as deploy or commit), and user-invocable: false means only the agent can, for background knowledge that isn't a command (Skills).

Going deeper: arguments, bundled scripts and live context
  • Arguments. /fix-issue 123 puts 123 into $ARGUMENTS. $0, $1… pick arguments by position, and an arguments: [issue, branch] header lets the body say $issue and $branch.
  • Bundled scripts. A script in the skill's folder is reached as ${CLAUDE_SKILL_DIR}/scripts/render.sh, so it works wherever the skill is installed. A script gives the same result every run, which is why quality-gate below carries one.
  • Live context. A line such as - Changed files: !`git diff --name-only` runs before the agent sees the skill, and the output replaces it. If that command fails or is denied, the skill doesn't run at all.

Going deeper: who may start a skill, and what it may pre-approve
  • disable-model-invocation: true: only you can start it, with /name. The docs suggest it for side effects "like /commit". This course leaves it off so the agent can run commit when a slice is done; the approval sits in step 6 and, from lesson 7, in an ask rule. Want the stricter form? Add the line.
  • allowed-tools: tools that run without asking while the skill runs. It restricts nothing. A commit skill must never pre-approve its own approval step, so check this field in any skill you copy.
  • The listing cuts descriptions at 1,536 characters. Old .claude/commands/ files still work; commands "have been merged into skills".

The quality gate: a skill that carries a script

"Test everything yourself" asks the model to remember the commands, their order, and to stop at the first failure. quality-gate puts that in a script:

The SKILL.md beside it carries the judgement a script can't: fix the cause, never skip or weaken a test to go green, never bend production code to suit a test tool, and after two failed fixes, use 1-3-1. Your repo's .gitattributes already keeps *.sh files LF, so the script runs from a Windows checkout too.

One folder, three tools

Codex and Antigravity read skills from .agents/skills/<name>/. Claude Code reads .claude/skills/<name>/, and a skill entry there "can be a symlink to a directory elsewhere on disk". So the real folders live in .agents/skills/, and .claude/skills/ gets one symlink (a tiny file that points at another path) per skill. Git stores a symlink as that path, so it travels with the repo.

Gotcha: a personal skill with the same name wins. The docs' order is "Enterprise over personal, and personal over project". A ~/.claude/skills/commit from some other project replaces your repo's /commit, so none of its gates run. If you have used Claude Code for a while, check before you rely on yours.

Let the agent write the next skill

You don't have to write every skill by hand. Anthropic's skill-creator plugin helps you draft a skill and then test it: it stores test prompts with the behaviour you expect, runs each in a clean subagent, grades the results, compares the skill against no skill, and tunes the description so the skill triggers when it should (Skills: creating skills with Claude's help).

A good habit: any multi-step instruction you type a second time is a skill waiting to be written. Ask skill-creator to draft it from what you just did, read the draft like any other diff, and commit it. A skill is still a request

A skill is text the model reads. Specific steps, loaded at the right moment, make the right thing far more likely, but nothing blocks the agent from skipping step 3, or from committing without the skill. Lesson 7 adds what the tool enforces:

6 · You approveAn ask permission rule on git commit
2, 3 · No build output, no secretsA git pre-commit hook, which runs for humans too

8 · Never pushAn ask rule on git push, and deny rules on force-push

Check yourself

Which part of a skill decides whether the agent picks it up on its own?

Only the name and description sit in context before the skill runs, and the agent matches your task against the description. That is why it says what the skill does and when to use it, key use case first.

You have ~/.claude/skills/commit from another project, and your repo has its own commit skill. What runs when you type /commit?

The order is enterprise, then personal, then project. Your repo's gates never run, so rename or move the personal skill.

The commit skill says "never push". Why does lesson 7 still add rules for git push?

A skill is text the model follows, so it raises the odds without blocking anything. Only the tool can refuse a command, which is what permission rules and git hooks do.

Exercise: two skills, two refusals, one commit through the skill

Exercise · about 45 min · you add: the commit and quality-gate skills, and the workflow pointing at them

Work in your practice repo (~/projects/stockapi), with this course's repo cloned beside it (~/projects/agent-harness-course). Windows: use WSL2 or Git Bash (setup).

  1. Start clean. git status should say nothing to commit, working tree clean.
  2. Check for a name clash. Run ls ~/.claude/skills. If it lists commit or quality-gate, the personal one would win: move it out of that folder for this course, or rename both its folder and its name: line (for example to my-commit).
  3. Copy the two skills. From the repo root: 
    mkdir -p .agents/skills
cp -r ../agent-harness-course/reference-solution/.agents/skills/commit .agents/skills/
cp -r ../agent-harness-course/reference-solution/.agents/skills/quality-gate .agents/skills/
  4. Make them yours. Read both SKILL.md files in full. In commit/SKILL.md step 4, replace the domain with your work email domain (or whichever domain you commit with). git config user.email should print an address on it.
  5. Point Claude Code at them. One symlink per skill: 
    mkdir -p .claude/skills
ln -s ../../.agents/skills/commit .claude/skills/commit
ln -s ../../.agents/skills/quality-gate .claude/skills/quality-gate
ls -l .claude/skills
    Each line should show ->; the target is relative to the link's folder, hence ../../. Git Bash: without Developer Mode, copy instead (cp -r .agents/skills/commit .agents/skills/quality-gate .claude/skills/) and re-copy after every edit.
  6. See them. Start a fresh session in Manual mode, claude --permission-mode default, and type /: both skills should be listed. (Session already open? Run /reload-skills.)
  7. Run the gate. Type /quality-gate. To the prompt for bash .agents/skills/quality-gate/gate.sh, answer Yes, not "Yes, and don't ask again": lesson 7 writes allow rules on purpose. Expect quality gate: green.
  8. Break it on purpose. In your editor, add three spaces before var builder in src/StockApi/Program.cs, save, and run /quality-gate again. It must stop at step 1 with GATE FAILED at format (ours printed error WHITESPACE: … Delete 3 characters.) and never reach build. Let the agent run dotnet format as its skill says; then git diff src/StockApi/Program.cs should be empty.
  9. Make /commit refuse. Force-stage a build file that .gitignore normally keeps out: 
    dotnet build
git add -f src/StockApi/obj/project.assets.json
    Run /commit. It should stop at step 2, name src/StockApi/obj/project.assets.json, and propose git restore --staged. Accept the restore; obj/ is already in .gitignore, so no new entry is needed. git status should no longer list the file as staged.
  10. Commit the skills through the skill. With nothing staged, run /commit. It should propose the new files under .agents/skills/ and .claude/skills/ and ask before staging; say yes. Read the drafted message (such as feat(harness): add commit and quality-gate skills) and approve it. Then: 
    git log -1 --format='%h %ae%n%B'
    Your work email, a conventional subject, and no Co-Authored-By or "Generated with" line.
  11. Point your rules at the skills. In docs/ai/workflow.md, step 4 becomes "run the quality-gate skill" and step 6 "run the commit skill; it drafts the message and waits for approval. Never push." Step 5 (review) stays manual until lesson 6. In the Definition of done in AGENTS.md, the format/build/test item becomes "the quality-gate skill passes" and the commit item names the commit skill. Commit both through /commit: docs(ai): point workflow at the skills.

Codex: it reads .agents/skills/ as they are, so skip the symlinks; type $quality-gate or $commit, and check the first commit message for any attribution line your Codex setup adds. Antigravity: the same folder works; type /quality-gate or /commit.

Done when: tick all four to earn the Skill Smith plaque
  • Both skills appear when you type /
  • /quality-gate stopped at GATE FAILED at format, then went green
  • /commit refused the obj/ file and named its path
  • The skills and docs(ai) commits went through /commit: work email, no AI trailer
