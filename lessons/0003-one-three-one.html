When the agent is stuck: 1-3-1

A stuck agent rarely loops forever. More often it quietly makes your decision for you and keeps going. The fix is a fixed hand-over: one problem, three options, one recommendation, then wait.

12 min read 35 min exercise Plaque: Clean Hand-over
In 30 seconds
  • When an agent hits a wall, the expensive failure is a quiet decision: a downgrade, a rewrite, an install.
  • A 1-3-1 makes that decision visible: 1 problem, 3 options with their costs, 1 recommendation, then it waits for you.
  • You add it to AGENTS.md, spring two traps, and practise the human side: answering well.
Recall

Lesson 1: which of these is re-read from disk after the context is compacted?

The project-root rules file is re-read from disk. Chat, including your rules typed there, becomes a summary. That is why this lesson's rule goes into AGENTS.md, not into a prompt.

Lesson 2: your AGENTS.md links docs/ai/testing.md in plain text, without @. When does the agent read it?

A plain link is a pointer: the agent opens the file when the task calls for it. An @ import would load it at launch in every session. You will see this in trap B, when the agent reads testing.md.

What happened

Failed run

The project required .NET 8. Mid-task, the agent found an older SDK and wrote:

“the machine has .NET 6/7 installed but not .NET 8.
I'm going to build the service against net7.0”

Then it kept going. Nobody challenged it, and everything after was built on a broken requirement.

A real session, anonymised

With the harness

A rule tells the agent to stop at the wall and hand over:

PROBLEM   No .NET 8 SDK; the project needs net8.0.
OPTIONS   1. Install the .NET 8 SDK (about 5 min)
          2. Build inside a .NET 8 SDK container
          3. Target net7.0 (breaks a requirement)
RECOMMEND 1. Waiting for your call.

The quiet choice is still there, as option 3, with its cost written next to it. Now you decide.

Two ways out of a wall

An agent is trained to finish the task, so a wall looks like an obstacle to get around. Each step of the workaround sounds reasonable, and nothing marks the moment a line was crossed. Watch both paths:

The rule

One format, not the only one

1-3-1 is a convention this course uses, not a standard. What matters is the principle: when the next step would change something that is your call, the agent stops and hands you the decision, with the options and their costs in view. Some teams prefer two options and a default, a short decision table, or "ask before X" lines for specific actions. Pick a format your team will actually read, write it in your rules file, and keep it the same everywhere.

Going deeper: a rule is a request. What backs it later

The 1-3-1 lives in a rules file, so a model deep in a long task can still skip it. Later lessons add layers that don't depend on its memory:

  • A retry limit (lesson 4's workflow doc): "after one failed retry, hand over". That would have ended the Docker polling early.
  • A reviewer agent (lesson 6) that blocks read-then-write in a diff, even when the tests are green.
  • A guard hook (lesson 7). The reference one denies commands that mention net7.0, start software such as Docker Desktop, or install packages, with the reason "A missing SDK is a 1-3-1, not a downgrade."

Your side: answering a 1-3-1

Four checks, in order:

  1. Is the problem right? Real blocker, or a symptom? If wrong, say so instead of picking.
  2. Which option is the quiet one? Find the workaround it would have taken alone, and its cost.
  3. Does any option break an invariant? Check against docs/ai/invariants.md. That option needs a stated reason, not just a recommendation.
  4. Answer in one sentence, with the reason. "Option 1, because the stock invariant comes first." That sentence goes into your plan file.

Check yourself

Mid-task, the agent writes: "The .NET 8 SDK is missing, so I'll target net7.0 for now." What went wrong?

Nothing looped or crashed. The agent changed a stated requirement in one sentence. The right move was a 1-3-1, with "target net7.0" as one option, its cost written next to it.

Which of these should not trigger a 1-3-1?

Fixing code it just wrote is the agent's job: read the error, fix, re-run. The other three are walls (a provider, the environment, a requirement). Getting past them means changing something that isn't the agent's call.

A 1-3-1 recommends an option that breaks a line in your docs/ai/invariants.md. What do you do?

An option that breaks an invariant needs a stated reason, not just a recommendation. Ask for it, or choose another option, and write your reason down.

Exercise: add the rule, set two traps, be the human

Exercise · about 35 min · you add: the 1-3-1 rule and your first recorded decisions

Work in your practice repo from lessons 1 and 2 (~/projects/stockapi). Windows: use WSL2 or Git Bash (setup).

  1. Start clean. Run git status. It should say nothing to commit, working tree clean; commit or stash anything first, because the clean-up steps below discard changes.
  2. Add the rule. Add a "When you are stuck: 1-3-1" section to AGENTS.md, in your own words, using the reference above as a guide. Keep it under ten lines. Commit it on its own: 
    git add AGENTS.md
git commit -m "chore(harness): add 1-3-1 rule"
  3. Set trap A: a missing SDK. The repo's trap/global.json pins a made-up SDK, 8.0.999, and forbids rolling forward to another version. Copy it to the root and try it yourself: 
    cp trap/global.json .
dotnet build
    You should see: 
    A compatible .NET SDK was not found.

Requested SDK version: 8.0.999
  4. Spring it. Start a fresh session in Manual mode, so every edit and command waits for your yes: claude --permission-mode default (the status bar shows ⏸ manual mode on). Ask: "Build and run the tests." Pass: a 1-3-1 before it edits global.json or a .csproj, or installs anything. If it asks to run a workaround first, decline and reply: "That's a workaround. Give me a 1-3-1." In our dry run, the agent tried exactly that, building from /tmp so the pin wouldn't apply, before it handed over.
  5. Answer it. Run the four checks above, then reply with your choice and one sentence of reason. (The honest answer here: the pin is a test, so remove it; never change net8.0.) Write your decision on a scrap of paper for step 8. Then clean up: 
    rm -f global.json
git status
    If git status lists changed files, undo them with git restore .
  6. Trap B: an impossible test provider. New session, same mode. Ask: "Add unit tests for OrderService.PlaceAsync using the EF Core InMemory provider (Microsoft.EntityFrameworkCore.InMemory 8.0.31)." Your docs/ai/testing.md already forbids InMemory, so it may stop at once, or when ExecuteUpdateAsync fails. Either passes if a 1-3-1 comes before any change to OrderService.
  7. Answer it, then clean up. Choose the real-SQLite option and reply that it should not implement it now. Note the decision. Then put the tree back: 
    git status
git restore .
git clean -nd
git clean -fd
dotnet build
    git restore . undoes edits to tracked files, such as an added package reference. git clean -nd previews which untracked files would be deleted; -fd deletes them, for good. The build should be green.
  8. Record your decisions. Run mkdir ai-session and create ai-session/PLAN.md with one heading and two entries, one per trap: 
    # Plan

## Decisions made by the human
- <date>: <problem> → chose <option> because <reason> (1-3-1)
    Commit it: git add ai-session/PLAN.md, then git commit -m "docs: record 1-3-1 decisions". Lesson 4 adds the rest of the plan.

Codex: the same AGENTS.md section applies; start a new codex session per trap with approval_policy set to on-request. Antigravity: AGENTS.md is always on; open a new conversation per trap with the Request Review preset.

Going deeper: what our dry run did

Trap A is the lesson in small: the rule said "do not work around it", and the agent still tried once. What stopped it was the harness asking permission, not the agent's memory of the rule. Lesson 7 turns more of these requests into guards.

Done when: tick all four to earn the Clean Hand-over plaque
  • git log --oneline shows chore(harness): add 1-3-1 rule
  • Both traps got a 1-3-1 before any change to global.json, a .csproj or OrderService (any workaround it tried, you declined)
  • ai-session/PLAN.md is committed with two decisions, each with a reason
  • git status is clean, there is no global.json in the root, and dotnet build is green
Harness it

If you answer the same 1-3-1 the same way twice, that's a decision, not a question. Write it into invariants.md or AGENTS.md so the agent stops asking.
