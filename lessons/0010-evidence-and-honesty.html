Evidence and honesty

Anything that shows how you worked (a plan, a tidy log, a reflection) can be produced afterwards, and an evaluator knows it. So the ranking is: what the tool recorded while you worked, then what git recorded, then files, and last of all what anyone, including an agent, wrote about it. Learn to produce the first kind and to say plainly when you can't.

Recall

After /clear, which instruction is still loaded?

Lesson 1: files in the repo root are loaded again in every session; conversation is gone. That is also why a transcript matters: it is the record of what was said and done in a session that no file keeps.

What does a correct 1-3-1 hand-over contain?

Lesson 3: then the agent waits for the human's decision. Today you'll record each 1-3-1 you answered in REFLECTION.md, with evidence.

The win

By the end your repo holds an exported transcript and a REFLECTION.md in which every entry points at a commit or a transcript line. You'll have run the evaluator's own hygiene commands on your repo, and you'll have fixed what they found forward, with new commits and no rewritten history.

What the harness does instead

Commits happen when each slice is green, through the commit skill, so timestamps show the real sequence. A permission policy doesn't auto-allow git rebase *, and the destructive guard refuses history rewrites outright. The evaluator's command git log --format='%ad' --date=iso | sort | uniq -c | sort -rn | head then finds nothing, because nothing was replayed.

A messy honest log costs you some points of style. A replayed one costs you the credibility of everything else in the repo.

What the harness does instead

The instinct to "rewrite the remote branch" is the wrong tool, and the force-push deny rule (lesson 7) protects the branch from the human as well as the agent. The revert is what you should do on purpose: it keeps both the mistake and its correction visible. Git's history is the second-strongest evidence you have. Don't spend it.

The evidence hierarchy

The evaluator's procedure (the checklist an evaluating agent follows when it marks a repo) opens with this ranking. It's the same order you should use on your own work:

RankEvidenceWhy it ranks there
1Raw session transcript (Claude Code .jsonl, Codex .jsonl, exported chat)Recorded by the tool as it happened; shows who asked for what
2Git history: file-add order, timestamps, authors, diffsHard to fake, but it can be replayed or rewritten (two of six were)
3Files in the repoShow what exists, not when or why it was written
4Narrative docs (PROCESS_NOTES, REFLECTION, SESSION_LOG, README)"These are CLAIMS. Usually agent-written. Verify each against 1–2; never score them as evidence alone."

Each item has an incident in this course. Trainee A's CLAUDE.md (rank 3) was credited as deliberate orchestration, but git order (rank 2) showed it arrived in c19c72a, 31 minutes after the last feature commit. Trainee D's PLAN.md was "written before implementation" (rank 4), but it was first committed in 1009656 together with the entire API, and git can't show it came first. Trainee C's "JWT rejected" (rank 4) was contradicted by a commit (rank 2) one minute later. The next assessment's format states the consequence: the harness is checked at 0:30, "so order is enforced by the format rather than reconstructed from git".

The evaluator labels each claim CONFIRMED, WRONG or UNVERIFIABLE, with a commit or transcript event as evidence. That is lesson 9's TRUE, STALE, UNVERIFIABLE under other names. Use the same three on your own docs, and write "I couldn't verify this" when it's the case. This course does it too: the badge unverified marks what its author couldn't confirm.

Exporting the evidence

The required submission has ai-session/<raw transcript> "exported, unedited". Two forms exist, and you want both:

  • Readable: /export [filename] "exports the current conversation as plain text. With a filename, writes directly to that file" (Commands).
  • Raw: Claude Code writes every message, tool use and result "to a plaintext JSONL file under ~/.claude/projects/" (How Claude Code works): ~/.claude/projects/<project>/<session>.jsonl (on Windows with Git Bash that is %USERPROFILE%\.claude\projects; in WSL2 it is under the Linux home folder where you run Claude Code), with subagent transcripts under <session>/subagents/. verified 2026-09-30 JSONL is "JSON Lines": one JSON object per line, so standard line tools work on it.

Before you commit a transcript

Transcripts are long, and they contain everything the agent saw. Trainee A's "contain local machine paths (C:\Users\<name>, E:\<work-folder>\…), which is harmless here but worth knowing before transcripts become a standard deliverable". The review scanned all committed transcripts for credentials and found none (two sk-… matches in Trainee E's were fragments inside encoded blobs). Two trainees pushed theirs only after review (Trainee C's 29,533-line transcript arrived in 939a0fd, right after the reviewed commit). Do the check first. (The review here is the report on the six repos; its quotes are reproduced in this course.)

  1. Look for paths and names: grep -nE '/home/|/Users/|C:\\Users' ai-session/*. A username in a path is normally fine. Decide on purpose.
  2. Scan for secrets by staging and scanning what's staged: git add ai-session/ && gitleaks git --pre-commit --staged --redact --no-banner. Your .githooks/pre-commit (lesson 7) runs the same scan at commit time. Its config-secret pattern check deliberately skips ai-session/, because a transcript quotes config on purpose and would trip it on harmless text; gitleaks still scans the transcript, so the secret scan is not skipped.
  3. If a real secret is in there, rotate the secret. Don't hand-edit the transcript, because an edited transcript is a narrative again. Tell the reviewer what you rotated and why.

REFLECTION.md: your rejections, with evidence

The assessment's "critical review of AI output" criterion asks whether you reviewed the AI's output. Its scoring rule: "Human-led review with visible rejections/changes → 4–5. Agent self-review only → max 3. Accepted a correctness regression or a false safety claim → max 2." A reflection that says "I carefully reviewed everything" has no evidence in it. The reference template makes the evidence column mandatory:

A row has this shape (an illustration, modelled on what the review says Trainee A did at their plan gate; the evidence cell is yours to fill):

WhenThe agent proposedI decidedWhyEvidence
Plan gatePersist Rejected ordersDeclineNot in the brief; scope creeptranscript-….jsonl:1482

Three rules for filling it in. First, no evidence, no row: if you can't find a hash or a line, either find it (grep -n "Rejected" ai-session/transcript-*.txt) or delete the row. Second, the agent's catches are not yours: a review the agent ran on its own diff belongs under "What the harness caught", where a reviewer agent is named, and not under "I rejected". Third, an empty table is an honest table. The review says of Trainee B that "decisions and uncertainties are written down in detail, rather than the work being presented as flawless", and that is a point in their favour; inventing rejections is how you earn a "docs contradicted by the repo → minus 1". Mind the asymmetry: a raw transcript in the reviewed commit scores "up to 5"; a "post-hoc reconstruction or summary only" scores "max 3".

Never rewrite history

The submission rule is short: "do not rewrite or squash history". Reasons, from the assessment review and the design notes: replayed history makes the evaluator distrust all of it ("history can be replayed or rewritten (two of six were)"); a rewritten remote can destroy the evidence you need; and rewriting shared history is precisely the power the deny rules in lesson 7 take from the agent. What you do instead is fix forward:

You findFix forwardWhat you leave honest
A commit you didn't want (Trainee A)git revert <hash>, a new commitBoth the mistake and the fix are in the log
bin/, obj/ or tmp/ trackedgit rm -r --cached <dir>, add to .gitignore, commitOld commits still contain them; say so
Wrong author email on old commitsSet user.email now; later commits are rightNote the earlier ones in REFLECTION
An AI trailer on old commitsFix the attribution setting and the commit-msg hook nowSame: note it
A secret committedRotate the secret first, then remove it in a new commitHistory still has it; the rotation makes that harmless

The last row is the rule that matters most: removing a secret from history doesn't un-leak it. Rotation does.

Three notes. No output is a pass for every grep line and for git ls-files | grep (an empty screen means nothing was found); the gitleaks run ends with no leaks found. On a fresh repo the first command shows one line (count 1, one timestamp), which is expected. Second, the evaluator's own notes write gitleaks detect; that subcommand has been deprecated since gitleaks v8.19.0, so the block above uses gitleaks git --redact --no-banner (gitleaks v8.30.1 · verified 2026-09-30). Third, the evaluator also runs a timing check: for each config file, git log --diff-filter=A --format='%h %ad %s' --date=iso -- <file>, compared with the first feature commit. Credit goes only to what was added before the work it claims to steer. Try it on AGENTS.md, your skills and .githooks/.

The procedure's last line for each trainee is "confidence, and what evidence was missing". Write that line about your own repo. It's the honesty habit in one sentence.

Exercise: audit your own repo, then fix forward

Exercise · ~35 min · adds: ai-session/transcript files and a filled REFLECTION.md
  1. Export both forms. Do this in the same session that did the work, before you /clear or quit: an empty new session exports nothing useful. Windows: run the terminal commands in WSL2 or Git Bash (see Before you start on the index). 
    mkdir -p ai-session
# in the agent:
/export ai-session/transcript-2026-09-30.txt       # use today's date
# in a terminal, find and copy the raw file:
ls -t ~/.claude/projects/$(pwd | sed 's|[^A-Za-z0-9]|-|g')/*.jsonl | head -3
cp ~/.claude/projects/<project>/<session>.jsonl ai-session/transcript-2026-09-30.jsonl
    (The folder under ~/.claude/projects/ is your repo's absolute path with every character that isn't a letter or digit turned into -, so /home/priya/stockapi becomes -home-priya-stockapi, and the $(pwd | sed …) above builds that name for you. Listing all projects at once with * would mix in other repos' transcripts, and you don't want those in your repository.) Don't open the files in an editor and save them.
  2. Count what your harness actually did with the grep … | sort | uniq -c line above. Write down the number of Skill, Agent and mcp__ calls. If a number is zero for something you've claimed, note that for step 5.
  3. Copy the template from reference-solution/ai-session/REFLECTION.md and fill it in. Minimum: three rows under "Where I rejected or changed AI output" (lesson 3's 1-3-1 answers, lesson 6's BLOCK, lesson 9's declined simplification are all candidates), each with a commit hash or grep -n line number. Every row must have evidence, or be deleted. If you end up with fewer than three rows, say so in the confidence line rather than inventing one: an honest short table beats a padded one.
  4. Run the evaluator's commands from the list above on your repo, plus the git log --diff-filter=A … timing check for AGENTS.md. Paste the raw output into a "Hygiene check" section at the bottom of REFLECTION.md.
  5. Fix forward anything it found, using the table above (new commits only). Examples: a same-second burst is just the starter import plus one commit, so say so, don't "fix" it. A tracked obj/ gets git rm -r --cached. A personal email on commit 1 gets one sentence in the reflection. No Co-authored-by lines is a pass. End with the confidence line: what I could not verify about my own repo.
  6. Check before you commit the transcript (paths, then gitleaks git --pre-commit --staged --redact --no-banner after git add ai-session/), then commit through /commit: docs(ai-session): add transcript and reflection.

Codex: find the newest file with ls -t ~/.codex/sessions/*/*/*/ | head (path unverified) and copy it the same way. Antigravity: use the conversation export, open the file to see what it contains, and record in REFLECTION.md that you could not verify a raw file location. That sentence is itself honest evidence.

Done when
  • ai-session/ holds an exported transcript, unedited, committed after the secret scan
  • Every row in REFLECTION.md has a commit hash or transcript line number
  • The hygiene output is in the file, and each finding was fixed with a new commit (git log has no rebase or force-push)
