Rules files: AGENTS.md as the single source of truth

Put the rules in one short, tool-neutral index file, link the detail from it, and commit it before any feature code, because a rules file written after the work steers nothing.

Recall

Lesson 1: which of these is still in force after you run /clear?

Only files are loaded again in a fresh session. Chat text and its summaries go with the conversation, and a clicked approval is a personal setting, not a rule the agent reads.

Lesson 1: what does plan mode let the agent do before you approve a plan?

Plan mode explores and does not edit your source files until you approve a plan. When auto mode is available, a classifier may approve shell commands while you plan. Lesson 4 builds a workflow on that gap.

The win

By the end, the practice repo has an AGENTS.md of about 40 lines plus three linked docs, committed as chore(harness): add agent rules before any feature code. A brand-new agent session will answer "what are this repo's invariants?" by naming the files it read.

What the harness does instead

The rules file is commit one, before the first feature. Anyone can then check the order with git, and the tool loads the file at the start of every session, so the rules are in context while the work happens, not after it.

That is how the assessment checks it, too. (The assessment is the graded agentic .NET exercise this course prepares you for.)

One file, every tool

AGENTS.md is "a simple, open format for guiding coding agents", described as a README for agents and stewarded by the Agentic AI Foundation under the Linux Foundation. The closest file to the one you are editing takes precedence. Suggested contents are the project overview, build and test commands, code style, testing instructions, security considerations and commit guidelines (agents.md). Codex and Antigravity read it; Claude Code does too, as of a recent version.

Claude Code reads it natively

Claude Code reads AGENTS.md as your project instructions when the repo has no CLAUDE.md (Memory: AGENTS.md). v2.1.277+ · verified 2026-09-30 Before v2.1.281, some sessions, such as those on Amazon Bedrock or with telemetry disabled, read CLAUDE.md only. Interactive sessions confirm it with a line such as no CLAUDE.md found; AGENTS.md loaded: /home/you/repo/AGENTS.md. Look for that line; it is your proof the file loaded.

The fallback: a CLAUDE.md that imports it

Use a CLAUDE.md with a one-line import (@path pulls another file's text into the context) in three cases: your Claude Code is older than v2.1.277, your session cannot load AGENTS.md, or you want Claude-only extras. The docs' own example:

"Keeping the import never makes Claude read AGENTS.md twice", so it is safe to keep. Nothing is duplicated: AGENTS.md stays the one source, and CLAUDE.md holds only what is Claude-specific (Memory: sharing one file).

The CLAUDE.local.md gotcha

A CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md in your working directory or any directory above it makes Claude Code read those and skip AGENTS.md. v2.1.277+ · verified 2026-09-30 Your own ~/.claude/CLAUDE.md and .claude/rules/ files do not count. So a trainee who adds a CLAUDE.local.md for private notes silently switches off the team's rules, on their machine only. No error, no warning; you just stop seeing the "AGENTS.md loaded" line. Two ways out: delete the file, or set Project instructions to claude-md-and-agents-md in /config to read both. You will trigger this deliberately in the exercise.

Keep it an index

The root file is loaded into every session, so every line in it costs context on every task. The docs: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." And the test for each line: "Would removing this cause Claude to make mistakes?" If not, cut it (Memory, Best practices). The course's reference file is 39 lines. It holds four things: the commands, a definition of done, the invariants in one line each, and links to files with the detail.

Your file will differ from this one, on purpose. Leave out the 1-3-1 section (lesson 3). Skills and reviewers do not exist yet, so your "done" says: format check, build and test pass, and the human approves the commit. Link only the docs you create in this exercise (docs/ai/invariants.md, testing.md, workflow.md). The reference also links docs/ai/conventions.md and docs/decisions/, which this course adds later; a link to a file that does not exist sends the agent hunting.

Two limits on this design. First, imports do not shrink the context: "Imports help you organize a long file but don't reduce its context cost, because imported files also load at launch" (Memory). That is why AGENTS.md links to docs/ai/*.md in plain text, without an @, so they are read on demand. Second, the file is advice, not a lock. An agent can still ignore a line; the guards in lesson 7 are what block. The rules file makes the right behaviour the default.

A nested file, and path-scoped rules

Some rules only matter in one place. A nested AGENTS.md carries them, and loads only when Claude reads a file in that directory. The reference repo has one for the test project:

Claude Code has a second, Claude-only way to do the same: files in .claude/rules/ with a paths: list of globs (filename patterns: * matches any name, ** any folders, so src/**/Data/*.cs means every .cs file in any Data folder) in their frontmatter (the frontmatter is the YAML block between --- lines at the top). "Path-scoped rules trigger when Claude reads files matching the pattern"; a rule with no paths loads always. Note the .claude/rules/ folder does not suppress AGENTS.md (Memory: path-specific rules).

Both load late, when the agent first touches a matching file. So anything that must hold for every task belongs in the root file, and anything a task in another folder can ignore belongs in a nested one. After a /compact they reload only as Claude reads matching files again (What survives compaction).

Commit it first

Three things make the order matter. Steering: a rule that exists when the first prompt is typed shapes the first slice; a rule written at the end documents it. Proof: an evaluator, a reviewer or you next month can check git log --diff-filter=A and see that the rules came before the work; that is the test the review applied to Trainee A and Trainee D. Blame: when the agent breaks an invariant, you need to know whether the rule was in context. A rules file that arrives with the code cannot answer that.

What goes where

"Put it in the rules file" is the default answer, and often the wrong one. Here are the five places a rule can live, and what each can and cannot do:

MechanismWhat it isEnforced?Use it for
Rules fileText loaded into every session (AGENTS.md)No, a requestCommands, invariants, definition of done
Output styleChanges how Claude Code talks to you; per user, saved in .claude/settings.local.jsonNo: "It doesn't guarantee that something always happens"Your own teaching mode, such as Learning (lesson 1)
SkillA named procedure the agent loads when you call it or its description matchesNo, but repeatableCommit, quality gate, scaffolds (lesson 5)
HookA script the tool runs on an event, such as before a tool call; it can blockYesDestructive-command guard (lesson 7)
SubagentA separate agent with its own context window and tool allowlistNo, but independentReviewing a diff the author cannot grade (lesson 6)

Sources: Output styles, Skills, Hooks, Subagents. The rule of thumb: if it must always hold, it will eventually need a hook or a permission rule behind it. If it is a procedure, make it a skill. If it is a fact the agent needs, it is a rules-file line, or a linked doc.

Check yourself

A teammate adds CLAUDE.local.md with personal notes to a repo that relies on AGENTS.md. On Claude Code v2.1.284, what happens by default?

A CLAUDE.local.md in the working directory or above counts as a CLAUDE.md, so AGENTS.md is not read. Nothing warns you; the "AGENTS.md loaded" line just disappears. Delete the file or set Project instructions to read both.

Your AGENTS.md has grown to 300 lines. Which change actually reduces what loads into every session?

Imported files load at launch too, so imports only reorganise. Path-scoped rules and nested files load when the agent reads a matching file, which is what removes the cost from unrelated tasks.

An evaluator wants proof that your rules steered the work. What evidence settles it?

Agent-written text and summaries are claims. Commit order is evidence, and it is what sank Trainee A's c19c72a (31 minutes after the last feature) and Trainee D's 1009656 (plan and code together).

Exercise: write the index and commit it first

Exercise · ~30 min · adds: AGENTS.md, docs/ai/ (3 files), tests/AGENTS.md

Work in your practice repo from lesson 1 (~/projects/stockapi). The reference solution is an answer key; write your own first and compare afterwards. Windows: run these in WSL2 or Git Bash (see Before you start on the index).

  1. Check your version: claude --version. On v2.1.277 or later you normally need no CLAUDE.md; before v2.1.281, some sessions (such as Amazon Bedrock or telemetry disabled) read CLAUDE.md only, and a one-line @AGENTS.md CLAUDE.md is the fallback (see "Going deeper" above). The version prints as a number such as 2.1.284; compare it with 2.1.277.
  2. Write AGENTS.md in the repo root by hand, about 40 lines, using the annotated example as a shape: what this is, Commands, Definition of done, Invariants (one line each), Workflow pointer, More context. For now, "done" is: format check, build and test pass, and the human approves the commit. Lessons 5 and 6 swap in the skills and reviewers. Leave out the 1-3-1 section; lesson 3 adds it. "The human approves the commit" means you read the message and say yes yourself; nothing enforces it yet.
  3. Create the docs/ai folder (mkdir -p docs/ai) and the linked files. Easiest start: copy reference-solution/docs/ai/invariants.md and testing.md from the course folder into your docs/ai/ and trim them to your repo. Or ask the agent to draft them from BRIEF.md (plan mode is fine), then edit every line yourself. Each file needs:
    • docs/ai/invariants.md: stock never below zero even under concurrency; one guarded UPDATE, never read-then-write; net8.0; out of scope (auth, UI, payments), with the sentence "Endpoints are exactly those in BRIEF.md plus the ones a human-approved plan adds."; no secrets in git.
    • docs/ai/testing.md: real SQLite, never the EF InMemory provider, and why.
    • docs/ai/workflow.md: a stub, "Plan first, then one slice at a time." Lesson 4 fills it in.
  4. Write tests/AGENTS.md, three or four lines of rules that apply only to tests.
  5. Ignore scratch files and secrets: open .gitignore in your editor and add two lines at the bottom, tmp/ and .env. Save it.
  6. Commit, naming the paths so nothing else sneaks in (Conventional Commits, from lesson 1): 
    git add AGENTS.md docs tests/AGENTS.md .gitignore
git commit -m "chore(harness): add agent rules"
git log --stat -1
    The stat shows only those files. No feature code exists yet; that is the point.
  7. Verify in a new session. Start a fresh agent session and ask: "What are this repo's invariants, and where did you read them?" In Claude Code, look for no CLAUDE.md found; AGENTS.md loaded: …, printed near your first message. Then run /context and find the memory files line. No such line? See the gotcha in step 9.
  8. Nested file. Ask: "Open tests/StockApi.Tests/ApiTests.cs and list the rules that apply to tests, and which files they came from." The answer should mention tests/AGENTS.md.
  9. The gotcha. Run echo "Prefer tabs." > CLAUDE.local.md, quit the agent (/exit), start it again in the same folder, and ask step 7's question again. The "AGENTS.md loaded" line is gone and the invariants are not known. Now rm CLAUDE.local.md, start another session, and confirm it is back. Do not commit that file.

Codex: start codex in the repo; it concatenates AGENTS.md files from the git root down, so tests/AGENTS.md joins when you work in tests/. There is no CLAUDE.local.md trap. Antigravity: open the folder; AGENTS.md is an always_on rule. To test a scoped rule, add .agents/rules/tests.md with trigger: glob and globs: for the tests folder.

Done when
  • git log --diff-filter=A --format='%h %ad %s' --date=iso -- AGENTS.md shows chore(harness): add agent rules, directly after the starter commit
  • wc -l AGENTS.md is well under 200 and the file links to docs/ai/*.md without @ imports
  • A fresh session names docs/ai/invariants.md (or AGENTS.md) as where it read the invariants
  • You watched CLAUDE.local.md switch AGENTS.md off, then deleted it and saw it load again
