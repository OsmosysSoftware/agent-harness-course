Rules files: AGENTS.md as the source of truth

Lesson 1 showed that a rule typed in chat fades. This lesson moves your rules into one short file that every tool loads on its own, and commits it before any feature code.

12 min read 30 min exercise Plaque: Rule Writer
In 30 seconds

  • Keep it an index of about 40 lines. Detail goes in linked files that are opened only when a task needs them.
  • Commit it first, then check a fresh session loaded it. A stray CLAUDE.local.md can switch it off without a warning.

One file, every tool

AGENTS.md is "a README for agents": a plain Markdown file of instructions for coding agents, an open format stewarded by the Agentic AI Foundation under the Linux Foundation (agents.md). Codex and Antigravity read it. Claude Code reads it natively too v2.1.277+ · verified 2026-10-01, but only when no CLAUDE file is in the way (Memory: AGENTS.md):

The check covers your working folder and every folder above it; your personal ~/.claude/CLAUDE.md and .claude/rules/ don't count. How to tell it loaded: An interactive session prints a line such as no CLAUDE.md found; AGENTS.md loaded: /home/you/projects/stockapi/AGENTS.md, and /memory lists the file's path. No line? Look for a CLAUDE file. To keep a CLAUDE.local.md and still read AGENTS.md, open /config and set Project instructions to claude-md-and-agents-md.

Going deeper: older versions and the @AGENTS.md fallback

Some sessions read CLAUDE.md only: versions before v2.1.277, sometimes the first session after upgrading to it, and before v2.1.281 some Amazon Bedrock or telemetry-off sessions. There, add a CLAUDE.md that imports AGENTS.md. An import (@path) pastes another file's text in at launch:

"Keeping the import never makes Claude read AGENTS.md twice." Don't write "read AGENTS.md" in words instead: Claude then sees it only if it decides to open it (Memory: earlier workarounds). Claude Code never reads AGENTS.local.md, AGENTS.override.md or .agents/.

Keep it an index

The root file loads into every session, so every line costs context on every task. Anthropic's guidance: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" (Memory). Aim much lower. Your root file holds what every task needs, one line per rule, and points to the rest:

Here is the shape for the practice repo. Your wording will differ; the sections shouldn't. Link only files that exist: a dead link sends the agent hunting.

Two limits. Imports don't shrink anything: imported files "also load at launch", so link detail files as plain paths, without @. And the file is advice, not a lock: Claude treats it "as context, not enforced configuration". It makes the right behaviour the default; lesson 7's guards are what block.

Going deeper: nested files, path-scoped rules, other tools

A nested AGENTS.md, such as tests/AGENTS.md, loads when Claude reads a file in that folder, deeper subfolders included (we checked: reading tests/StockApi.Tests/ApiTests.cs loaded it, v2.1.286).

Claude Code also has .claude/rules/*.md. A rule whose frontmatter (the YAML block between --- lines at the top) lists paths: globs (filename patterns; ** means any folders) loads only when Claude reads a matching file. Without paths: it always loads (Path-specific rules).

Where instructions live: the layers

The repo's rules file is one layer of several. Claude Code reads them in order, broadest first, and adds them all together: nothing overrides anything. If two layers disagree, Claude "may pick one arbitrarily", so the job is to keep each fact in exactly one layer (Memory: where to put CLAUDE.md files verified 2026-10-01).

  1. Organisation/etc/claude-code/CLAUDE.md (Linux/WSL; macOS and Windows have their own path)Set by IT for every repo on the machine. You can't exclude it.
  2. You, everywhere~/.claude/CLAUDE.md and ~/.claude/rules/Your personal style and habits, in every project. Never project facts: your teammates don't have this file.
  3. The projectAGENTS.md at the repo root (or CLAUDE.md, .claude/CLAUDE.md)The team's rules, committed. Files in folders above where you start also load.
  4. You, this projectCLAUDE.local.md, git-ignoredYour sandbox URL, your test data. Careful: it switches AGENTS.md off (step 3 of the diagram above).
  5. A folder or modulesrc/Orders/AGENTS.md, tests/AGENTS.mdLoads only when Claude reads a file in that folder, so other tasks don't pay for it.
  6. A file type.claude/rules/efcore.md with paths:Loads only when Claude reads a matching file.

Three habits keep the layers useful. Check what loaded with /context, under Memory files; on Claude Code v2.1.283 or later, /doctor prompt-audit looks for contradictions across them. In a monorepo, start Claude in your module's folder: the folders above still load, the neighbours' don't, and a claudeMdExcludes list in your .claude/settings.local.json skips another team's file. Keep each file short: the docs suggest under 200 lines, because "longer files consume more context and reduce adherence".

Commit it first

Lesson 1's developer wrote CLAUDE.md at the end of a 356-turn session, so it steered nothing. Order matters twice. Steering: a rule that exists at the first prompt shapes the first slice; one written at the end only describes it. Proof: git records when the file first appeared:

git log --diff-filter=A --format='%h %ad %s' --date=iso -- AGENTS.md

That proves order only if the file arrives alone. In another session the plan landed in the same commit as the whole API, every box ticked, so nothing shows it came first.

Check yourself

Your repo relies on AGENTS.md. You add CLAUDE.local.md with private notes. What does Claude Code read by default?

CLAUDE.local.md counts as a CLAUDE file, so AGENTS.md is skipped, with no error. Delete the file, or set Project instructions to claude-md-and-agents-md in /config.

Your AGENTS.md has grown to 300 lines. Which change cuts what loads into every session?

Imported files load at launch too, so imports only reorganise. Path-scoped rules and nested AGENTS.md files load when Claude reads a matching file, so unrelated tasks don't pay for them.

How can a reviewer tell your rules steered the work, rather than being written afterwards?

Length and the agent's own summary are claims. Commit order is evidence: git log --diff-filter=A shows when the file first appeared, and whether it arrived alone.

What would you do?

A teammate ran /init, and it wrote a CLAUDE.md into a repo that already relies on AGENTS.md. What do you do with the new file?

A CLAUDE file switches AGENTS.md off. The @AGENTS.md import pulls it back in, read once. Written as words, Claude sees it only if it decides to open it.

Exercise: write the index and commit it first

Exercise · about 30 min · you add: AGENTS.md, docs/ai/ (3 files), tests/AGENTS.md

Work in your practice repo from lesson 1 (~/projects/stockapi), before any feature code. Windows: use WSL2 or Git Bash (setup).

  1. Run claude --version. You need 2.1.277 or later; on anything older, update Claude Code or use the @AGENTS.md fallback above.
  2. Write AGENTS.md in the repo root by hand, 30 to 40 lines, following the shape above. Nothing enforces "the human approves the commit" yet; you do.
  3. Create the detail files, starting from the course's reference solution: 
    mkdir -p docs/ai
cp ../agent-harness-course/reference-solution/docs/ai/invariants.md docs/ai/
cp ../agent-harness-course/reference-solution/docs/ai/testing.md docs/ai/
printf '# Workflow\n\nPlan first, then one slice at a time.\n' > docs/ai/workflow.md
grep -nE 'ConcurrencyTests|decisions/|1-3-1' docs/ai/*.md
    The grep finds lines about things your repo doesn't have yet (a concurrency test, decision records, lesson 3's 1-3-1). Delete or reword them, then read both files end to end.
  4. Write tests/AGENTS.md: three or four test-only rules, such as "real SQLite, never EF InMemory", "never weaken a test to make it pass", and a last line pointing to ../docs/ai/testing.md.
  5. Keep scratch files and secrets out of git: printf 'tmp/\n.env\n' >> .gitignore, then tail -3 .gitignore to check.
  6. Commit, naming the paths so nothing else sneaks in: 
    git add AGENTS.md docs tests/AGENTS.md .gitignore
git commit -m "chore(harness): add agent rules"
git show --stat HEAD
    Expect six files: AGENTS.md, .gitignore, three under docs/ai/ and tests/AGENTS.md.
  7. Verify in a fresh session. Start claude in the repo root and look for the AGENTS.md loaded line. Ask: "Without opening any files: what are this repo's invariants, and which file did your project instructions come from?" Then run /memory and find the AGENTS.md path. (On your first session after an upgrade it may not load yet; start one more.)
  8. Nested file. Ask: "Open tests/StockApi.Tests/ApiTests.cs. Did another instruction file load when you read it? Name it." It should name tests/AGENTS.md.
  9. The gotcha. Run echo "Prefer tabs." > CLAUDE.local.md, leave with /exit, start claude again and repeat step 7's question. The loaded line is gone, and the answer comes from CLAUDE.local.md. Run rm CLAUDE.local.md, start one more session and confirm AGENTS.md is back.

Codex: tests/AGENTS.md applies only if you start codex inside tests/, so skip steps 8 and 9. Antigravity: AGENTS.md is always on; for test-only rules use .agents/rules/tests.md with trigger: glob (Antigravity rules); skip step 9.

Done when: tick all four to earn the Rule Writer plaque
  • git log --oneline shows chore(harness): add agent rules directly after the starter commit
  • wc -l AGENTS.md is under 60, and it links docs/ai/*.md as plain paths, without @
  • A fresh session named AGENTS.md without opening files, and /memory lists it
  • You watched CLAUDE.local.md switch AGENTS.md off, deleted it, and saw it load again
Worth installing or reading
