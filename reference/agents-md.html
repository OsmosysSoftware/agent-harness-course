AGENTS.md structure

The rules file is an index of about 40 lines: commands, definition of done, invariants, 1-3-1, links. Commit it before any feature code. This is one working shape: keep the sections, word them for your project.

Claude Code only: the quick viewClaude Code reads AGENTS.md natively (v2.1.277+) when no CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md exists in the folder or above. The root file is re-read from disk after /compact. A nested tests/AGENTS.md loads when Claude reads a file there. .claude/rules/*.md with paths: loads only for matching files. Aim for under 200 lines per file, and about 40 for the index. Legend: verified 2026-09-30 = checked against the docs on that date; unverified = test it yourself before relying on it. Skip the Codex and Antigravity columns unless you use them.

The index skeleton (~40 lines)

The rules file is an index: it gives the rules that must always hold, and links to depth.

What each section is for

SectionHoldsWhy it is here
One line + stackWhat the thing is, .NET version, test framework, where the brief isOrientation in 2 lines. The agent cannot ask "what is this?" cheaply.
CommandsExact build, test, format, run commandsWrong guesses cost a turn each. Copy-paste beats description.
Definition of done3 to 5 numbered, checkable conditions"Done" becomes evidence, not opinion. Names the skill and reviewer to run.
InvariantsRules that must survive any refactor; forbidden patterns; out of scope; secretsThe part the agent must never trade for a green test. One line each; depth lives in docs/ai/invariants.md.
When stuck: 1-3-1The hand-over format and what triggers itTurns a silent decision into a question (sheet).
WorkflowOne linkPlan, slice, gate, review, commit. Kept out of the index so the index stays short.
More contextLinks, one per topic, with "read when relevant"Progressive disclosure: depth is loaded only when the task needs it.

The pruning testFor each line ask: "Would removing this cause the agent to make mistakes?" If not, cut it. (Claude Code best practices; target under 200 lines per file.)

Appendix: the reference solution's AGENTS.md, verbatim

What not to put in

Do not put inWhyPut it instead
Narrative ("we decided to use SQLite because...")The agent reads every line every session; story costs context and adds no ruleAn ADR (architecture decision record: a short "this is deliberate, here is why" file) in docs/decisions/, linked from the index
How-to for humans (clone, install, run the UI)Humans need steps; agents need constraintsREADME.md
Long code blocksThey go stale and the agent copies them literallyA pointer to the reference shape: "copy ProductsController"
Text duplicated from other docsTwo copies drift; the agent obeys whichever it saw lastOne home, plain link from the index
Rules for one folder onlyLoads everywhere for no benefitNested tests/AGENTS.md or a path-scoped rule
Things the tool already enforcesProse is weaker than a guardA permission rule, hook or test (sheet)

Commit-it-first checklist

  • Written before any feature code, committed as chore(harness): add agent rules (in one real session the rules file was written at the very end, so it steered nothing).
  • No CLAUDE.md or CLAUDE.local.md next to it (or one that only says @AGENTS.md).
  • Under ~40 lines; every line passes the pruning test.
  • Commands run as written (paste them into a terminal once).
  • Every invariant names its forbidden pattern and, where possible, the guard test.
  • The 1-3-1 section is in, and "never install, launch, downgrade or delete" is in it.
  • Every link resolves to a file that exists.
  • .gitignore has bin/ obj/ tmp/ *.db .env.
  • Checked in a NEW session: "What are this repo's invariants, and where did you read them?"
